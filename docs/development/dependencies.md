# Set up your build tools

[Docs home](../README.md) · [Build from source](building.md)

This page is for building Terlox from source. If you just want to use the app,
follow [Install Terlox](../getting-started/install.md). Release packages include
Qt and the terminal's other runtime components.

## What each tool does

| Tool | Why Terlox needs it | Get it |
| --- | --- | --- |
| C++ compiler and OS SDK | Compile the app and connect it to native window and terminal APIs | Windows and macOS steps below; Linux uses GCC or Clang |
| Qt desktop kit | Provides windows, fonts, input and the rendering framework | [Qt installer](https://www.qt.io/development/download-qt-installer-oss) |
| CMake | Reads the project's build rules and finds its libraries | [CMake downloads](https://cmake.org/download/) |
| Ninja | Runs the compile and link commands generated by CMake | [Ninja downloads](https://ninja-build.org/) |
| Python | Runs packaging scripts and repository checks | [Python downloads](https://www.python.org/downloads/) |
| Git | Downloads the source and records changes | [Git downloads](https://git-scm.com/downloads/) |
| GitHub CLI (`gh`) | Starts remote builds and uploads release files; optional for local development | [GitHub CLI installation](https://cli.github.com/) |

Use a supported Python 3 release. The C++ language standard and minimum Qt/CMake
requirements are recorded in [CMakeLists.txt](../../CMakeLists.txt). To match the
project's build environment, use the Qt kit selected in the
[build workflow](../../.github/workflows/build.yml). Those files are the source
of truth for tool versions.

## Windows

1. Install [Microsoft's C++ Build Tools](https://learn.microsoft.com/en-us/cpp/overview/acquire-msvc).
   In Visual Studio Installer, select **Desktop development with C++**. Include
   the x64/x86 MSVC compiler, a Windows 11 SDK and **C++ CMake tools for Windows**.
   The CMake tools include Ninja. You can modify an existing Visual Studio
   installation instead of installing another copy.
2. Install [Python](https://www.python.org/downloads/windows/) and
   [Git for Windows](https://git-scm.com/downloads/win). Open a new PowerShell
   window afterward so it picks up their commands.
3. Install the Qt desktop kit described below. Choose the **MSVC 64-bit** kit
   that matches your compiler, rather than a MinGW kit.

Set `QT_ROOT_DIR` to that kit's folder. Replace the example path with your own;
the folder should contain `bin`, `include` and `lib`:

```powershell
$env:QT_ROOT_DIR = 'C:\Qt\your-desktop-kit'
python --version
git --version
& "$env:QT_ROOT_DIR\bin\qmake.exe" -query QT_VERSION
```

These settings apply to the current PowerShell window. The Windows build script
finds Visual Studio's compiler, CMake and Ninja itself, so you don't have to add
their internal folders to your permanent PATH. Continue with
[Build from source](building.md).

## Linux

On Debian or Ubuntu, install the compiler and general build tools:

```sh
sudo apt update
sudo apt install build-essential cmake ninja-build python3 python3-pip git
```

Install the graphics, keyboard and font libraries used by the desktop Qt kit:

```sh
sudo apt install libgl1-mesa-dev libxkbcommon-dev libxcb-cursor0 libfontconfig1
```

Qt's [Linux dependency list](https://doc.qt.io/qt-6/linux-requirements.html)
covers additional libraries your distribution or Qt kit may need. On another
distribution, use its package manager to install the equivalents.

For `.deb` and AppImage packaging, also install:

```sh
sudo apt install dpkg-dev file patchelf desktop-file-utils
```

`dpkg-dev` supplies Debian packaging tools and dependency inspection. `file`
identifies binaries, `patchelf` adjusts where bundled libraries are found, and
`desktop-file-utils` checks application launchers. You can skip this group if
you only want to compile and run the app.

Install a Qt desktop kit using the next section. A distribution's Qt package
can also work if it meets the project's requirement; older distributions may
ship a Qt release that is too old. Point your shell at the chosen kit:

```sh
export QT_ROOT_DIR="/path/to/Qt/your-desktop-kit"
export PATH="$QT_ROOT_DIR/bin:$PATH"
cmake --version
ninja --version
python3 --version
qmake -query QT_VERSION
```

Some installations call the last command `qmake6`. Use `python3` wherever the
repository's instructions say `python` if that is your system's command name.
These exports apply to the current terminal session.

## macOS

Install Apple's [Command Line Tools](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools/):

```sh
xcode-select --install
```

They provide Clang, the macOS SDK and tools such as `pkgbuild`. A full Xcode
installation can provide them too.

With [Homebrew](https://brew.sh/) installed, get the remaining tools:

```sh
brew install cmake ninja python git
```

Use the Qt installer below, or install the
[Homebrew Qt package](https://formulae.brew.sh/formula/qt):

```sh
brew install qt
export QT_ROOT_DIR="$(brew --prefix qt)"
export PATH="$QT_ROOT_DIR/bin:$PATH"
```

For an installer-managed Qt kit, replace the `QT_ROOT_DIR` value with its folder.
Use a kit that supports your Mac's architecture. Check `cmake --version`,
`ninja --version`, `python3 --version` and `qmake -query QT_VERSION`, then continue
with the build guide. Signing and notarization are covered in the
[release guide](releases.md).

## Choose the Qt components

Download the [open-source Qt installer](https://www.qt.io/development/download-qt-installer-oss)
for your OS. Sign in with a Qt account when prompted. In component selection,
choose a supported **desktop** kit for your compiler and architecture. Qt's
[installation guide](https://doc.qt.io/qt-6/qt-online-installation.html) shows the
installer steps.

Terlox uses Core, Gui, Widgets, Quick, QuickWidgets, Network and Test. Keep the desktop
kit's base libraries, Qt Declarative/Quick and test support selected. You don't
need mobile kits, WebEngine or a full set of optional modules. Qt Creator is an
optional editor; you can build from the command line without it.

The kit includes `qmake`, deployment tools and CMake package files. Setting
`QT_ROOT_DIR` tells Terlox which kit to use; adding its `bin` directory to PATH
lets the Unix packagers find the deployment tools. Keep the same kit for building
and packaging a given release.

## What is already included or downloaded for you

| Component | Where it comes from | What it does |
| --- | --- | --- |
| libvterm | Included in `dependencies/libvterm` | Interprets terminal output and keeps screen cells |
| Cascadia Mono | Included in `dependencies/fonts` | Supplies the default terminal font |
| [NSIS](https://nsis.sourceforge.io/Download) | Downloaded by the Windows packager | Builds the setup EXE and uninstaller |
| [linuxdeploy](https://github.com/linuxdeploy/linuxdeploy) and its Qt plugin | Downloaded by the Linux packager | Collects libraries for the AppImage |
| [Microsoft console runtime](https://github.com/microsoft/terminal) | Downloaded by the Windows build/package scripts | Provides the Windows console host used by terminal handoff |

You don't need to install these separately. Download URLs and checksums live in
[`installer/packaging/tools.json`](../../installer/packaging/tools.json).
Packaging downloads are cached under `.tools` and need network access on the
first run. The included components' licenses are listed in
[Third-party notices](../Dependencies.md).

## Optional release tools

Install [GitHub CLI](https://cli.github.com/) if you want to build every platform
through Actions or upload releases. Run `gh auth login` and follow its prompts.
Remote packaging only needs Git, Python and `gh` on your computer; the GitHub
runners supply their own compiler and Qt installation.

Vim is optional for local tests. A test that needs it is skipped when it isn't
installed. Ordinary shell use and the other tests don't require it.
