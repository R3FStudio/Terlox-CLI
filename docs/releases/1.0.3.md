## Changes in V1.0.3

Development release. Further testing is needed for interactive resizing, display scaling, and platform-specific keyboard behavior.

### Bug fixes

- **Packaging downloads:** retry temporary failures, including HTTP 504, up to five attempts with exponential backoff. Checksum mismatches and permanent HTTP errors still stop packaging.
- **Download caching:** verify downloads before caching them and replace cached files through a temporary file.
- **Large-output memory growth:** bound the in-memory scrollback cache to 32 MiB per session and page older lines to compressed temporary storage instead of discarding them. The configured positive line count now limits cached rows, not total retained history.
- **Output flooding the UI:** cap queued process output at 1 MiB per session, apply pipe backpressure, and deliver output in batches of up to 64 KiB.
- **Session exit and shutdown:** deliver final queued output before reporting process exit and unblock pending output delivery during shutdown.
- **Resize stalls:** coalesce grid resize requests on a 16 ms timer, skip unchanged grid dimensions, retain glyph textures when only window dimensions change, and restrict frame generation to the visible viewport.
- **Text zoom overhead:** avoid reapplying native background effects during text-only zoom.
- **Windows resize blocking:** move ConPTY resize calls off the UI thread.
- **Clipboard shortcuts:** use Command+A/C/V on macOS, Ctrl+A/C/V on Windows, and Ctrl+Shift+A/C/V on Linux. Windows Ctrl+C interrupts when nothing is selected; Linux plain Ctrl+A/C/V and macOS physical Control keys remain available to shell applications.
- **Unix shell setup:** fresh configurations prefer a discovered native shell, honoring `SHELL` where it matches a profile. Explicit saved defaults are preserved.
- **Custom-shell source errors:** correctly parse `\.` and explain that `source` and `.` require a native shell, instead of reporting a missing executable. Full POSIX scripting and shell functions remain unsupported in `terloxsh`.

### Features and additions

- **Disk-backed scrollback:** scrolling up reloads older text from private temporary files. History remains accessible beyond the RAM cache and configured cached-row count. Clearing or closing the session removes that session’s archive. A zero scrollback setting explicitly disables history.

- **Version and stats report:** `terlox --version` prints version, system/build information, and buffer limits without opening a GUI.
- **Built-in system report:** `fastfetch`, `fetch`, `sysinfo`, and `version` in `terloxsh` print Terlox's own report without an additional download. Upstream Fastfetch and its options are not included.
- **Full terminal clearing:** `terlox clear`, `/terlox clear`, and the **Clear terminal** menu action clear visible text and retained scrollback in the current session. The `terloxsh` `clear` builtin now clears scrollback too.
- **Additional clipboard bindings:** Ctrl+Insert copies and Shift+Insert pastes on Linux and Windows.
- **CI tool cache:** cache pinned packaging tools between workflow runs.

### Known limits

- The scrollback and output-queue budgets do not cap total application or child-process memory. Screens, images, glyph textures, Qt, and running programs use additional memory.
- Archived history uses temporary-disk space and belongs to the current session. Closing the session or clearing its history deletes it; it is not restored after restarting the app.
- Disk usage grows with retained output. Storage failures produce a warning; additional history cannot be guaranteed if disk space is exhausted.
- Resize changes have not been benchmarked across different GPUs, compositors, or monitor scaling configurations.
- GUI checks used the offscreen software backend; they do not establish correct behavior on every desktop.

## Validation

- Regression coverage includes reloading old text beyond the RAM and row-cache limits, preserving cell styles, reverse popping across the disk/RAM boundary during resize, scrollbar access, and clearing disk history.
- Native builds, automated tests, packaging, and installer smoke checks run in CI on Windows x64, Linux x64, macOS arm64, and macOS x64.
- GUI tests use the offscreen software backend; interactive testing on additional desktops is still needed.
